## 1. 接手先读什么

1. 读本手册，区分“已实现”“待核对”“后续建设”。
2. 读对应展会主档，确认展会身份、届次、展位和当前有效清单；不要根据目录名猜展会名称。
3. 读对应的拓扑、线材供电资料和用户最新确认内容；出现冲突时保留来源，列出待确认项。
4. 确认页面当前布局是否有浏览器内编辑结果。源码初始值不等于用户编辑后的最终稿。
5. 按本文工作流程更新当前方案。产品参数、接口、供电和施工尺寸不明时，不补造已确认值。

## 2. 当前场景基线：已实现

### 2.1 展会身份与尺寸口径

本项目目录为 `迪拜GESS/2026-12`，既有主档记载项目 ID 为 `DXB-EXPO-2026`，实际名称为 **GITEX GLOBAL Dubai 2026**、展位 `H3-A52`。这是本地项目记录，不是本次重新核验展会日程的结果。

当前 POC 为 5,000 × 5,000 mm 外轮廓、4,000 mm 墙高、200 mm 墙厚，前方开放、左右及后方三面墙。门头为简化示意。线材估算文档出现 5 × 5 × 2.8 m，**墙高尚需与最终施工图对齐，不能把 4 m 和 2.8 m 混用。**

尺寸统一用 mm；渲染时转换成 m。原点在外轮廓地面中心：X 向右、Y 向上、Z 朝入口。位置 X/Z 为中心坐标，`bottom` 为物件下沿离地。左右柜的宽度沿 Z 轴，深度沿 X 轴。当前后墙内表面 Z=-2,300 mm，两侧内表面 X=±2,300 mm；前方不额外扣除图纸中的 100 mm 边条。

连接 ID 为“源设备 ID + 线缆类型”，例如 `back-a-hdmi`。当前端点是占位坐标，不是真实接口孔位；表中起点/终点描述渲染连线，真实信号方向仍须按接口核对（如 HDMI 从电脑输出到 IFP 输入、USB 触控回传到主机）。

当前只覆盖四块主 IFP；两块小屏、会议设备及笔记本自身供电未接线，也没有服务器 LAN。三只排插只是设备电源线的终点，尚未连接到场馆实际取电点。完整项目的“地插 → PDU → 设备”供电链仍待补齐。

当前模拟器颜色遵循：LAN/Ethernet/PoE+ 蓝 #0074D9；HDMI 红 #FF4136；USB 黄 #FFDC00；RS232/RS485 紫 #B10DC9；Audio 绿 #2ECC40；IR 灰 #AAAAAA；Relay 橙 #FF851B；电源与Relay共用橙 #FF851B。图例只显示当前方案实际使用的线缆类型；未使用类型不显示。虚线表示隐藏段。地板下默认 Y=-30 mm 仅为显示层次，不是已确认的开槽深度。程序未计算采购线长、真实接口兼容性、电气负载或施工条件。

### 2.4 检修口和穿线孔要分开管理

| 类别 | 用途 | 当前资料中的尺寸 | 当前模拟器状态 |
| --- | --- | --- | --- |
| 大检修口 | 低位出线、检修及路径讨论 | POC 1,000 × 250，下沿 350 mm；示意待核对 | 三面墙已建开口、边框；可移动和改宽高 |
| 屏后穿线孔 | 屏幕后线缆进入墙体 | 项目主档及估算记录 80 × 80 mm | 未单独建模 |
| 墙下及柜背对穿孔／槽 | 墙内线缆进入柜体 | 项目资料记录 150 × 150 mm 或长开槽 | 未单独建模 |

三种开口不能互相替代尺寸。每处应分别记录墙面、沿墙位置、下沿高度、尺寸、对应设备、用途、资料依据及确认状态；墙孔与柜背孔需核对是否对齐。现在的大检修口是模拟器中的真实矩形几何缺口，不是已批准施工开孔。

## 3. 运行、操作与保存

### 3.1 启动和检查

Node.js 要求：20.19+ 或 22.12+（与当前 Vite 依赖要求一致）。在 PowerShell 中：

```powershell
cd D:\Github\IQ\zhanhui\booth-poc
npm install
npm run dev -- --port 5173
```

打开终端打印的实际 URL；通常为 `http://127.0.0.1:5173/`，端口占用时可能改变。依赖未变化且已安装时可跳过 `npm install`。不要直接双击 HTML 运行。

```powershell
npm test
npm run build
npm run preview
```

测试覆盖尺寸约束、重叠、v1 迁移、v2 数据往返、附属设备跟随和接线关系。构建输出至 `dist/`；预览网址以终端输出为准。单元测试通过不等于页面导出链路已验证，见下节已知问题。

### 3.2 操作

- 拖动空白处旋转，滚轮缩放，右键拖动平移；正视、俯视、左右墙视图用于检查安装高度及平面位置。
- 点击清单或物件选择；拖动彩色轴移动。墙上物件沿墙移动、升降，柜子与讲台沿地面移动。
- 参数面板输入精确毫米值；50 mm 吸附只影响拖动。
- 选择检修口，修改宽高、下沿及沿墙位置；点“调整开口高度”，拖动顶部绿色手柄，下沿保持固定。
- 笔记本限定在所属柜顶，排插跟随柜体或后墙检修口；移动柜子不会移动墙上的检修口。
- 开启走线示意后，墙、地板、柜体透明化；可分别开关当前方案实际使用的线缆类型；颜色规则见本手册 §2.3。选中设备、柜体或检修口突出关联线，属性面板列出连接名称。
- 撤销／重做最多保留本次会话最近 60 步；刷新后没有操作历史。恢复初始布局会回到代码默认值。

### 3.3 保存现状与限制（POC 03）

自动保存键仍为`iq-dubai-booth-v1`，内容及导出为version 3，21件。v1旧11件、v2旧19件导入时保留用户位置并补齐新增物件。导出版本错误已修复，回归覆盖v3往返与旧版迁移。浏览器真实按钮验证结果以[PAGES.md](./PAGES.md)及发布证据为准。

连接表及展位尺寸仍固定；改JSON不能实现任意展位或自定义接线。浏览器保存只属于同一浏览器和源地址，不能代替共享交接文件。正式方案仍需用户核对位置、尺寸、附属关系、线路与来源后归档。

## 4. 收到新展会参数后怎么做

### 4.1 数据来源：成熟产品与新品两路输入

两路来源汇合为本届项目参数记录，再进入空间与接线规划。**新品没有稳定参数表，不阻止先做布局讨论。**

| 数据来源 | 处理方式 | 不足时的处理 |
| --- | --- | --- |
| 成熟、可检索型号 | 调用 `product-comparison` 的 `lookup` 流程，先读分类索引，再读精确型号资料 | 缺项再查对应规格书、工程图或用户资料；不凭名称猜数值 |
| 尚未入库／参数剧烈变化的新品 | 根据用户口述、消息、草图或临时表建立项目内临时产品记录；保留暂定型号与实例 ID | 逐字段标“用户确认”“暂估”“待确认”，不强制先整理完整参数表或写入共享产品库 |

执行产品查询时重新读取 skill 的当前规则。Q-NEX 中控及智能讲台按 L1、IFP／IQ／IQVideo 按 L2，混合清单按需读取两者；IQPodium/PD150 属于 L2 教学外设，不等同于 L1 Q-NEX 智能讲台。第三方设备仅在清单明确涉及时按相应索引查询，项目专供产品遵守原 skill 的 L4 可见性要求。这里的“临时新品记录”是项目数据，不意味着自动改写产品库分级。

每项参数记录数值、单位、口径、来源、核对日期、确认状态。区分裸机、带底座/支架与包装尺寸；不能由屏幕英寸推导整机外形。功率区分典型、最大、适配器额定值；缺失记“待确认”，不记0。使用外置 OPS 或适配器时，核对整机功率是否已经包含，避免重复计入。只有明确确认无源的物件才可标“不需供电”。

新品未知尺寸可经说明使用暂估占位，标出占位尺寸，不能写成该型号真实规格；未知接口先记录演示意图和待定端口，未知功耗单列待补，不提供看似完整的总负载。参数更新后只更新本届当前记录与方案，并重新检查受影响的摆位、开孔、信号和供电。过程仍由项目 Markdown／Excel 承接；其他展会已确认参数不自动改变。

查询缺项不自动授权维护共享产品库。新品稳定后若需要入库，另按产品 skill 的维护规则补数据及索引。本交接任务不创建产品对比交付件，也不执行产品库维护或售前阶段登记。

### 4.2 统一工作步骤

1. **确认输入**：展会身份、长宽高口径、开口方向、展品型号/数量、每面墙分配；列出柜体、安装高度、取电与演示关系等缺项。
2. **形成项目参数**：按上述两路获取资料；每个实例绑定型号或临时产品记录。同型号多台分别编号，不与资产序列号混用。
3. **摆位**：建立墙、地板、柜体、台面和展品；使用真实外形核对安装高度、边界和动线，区分已确认布局与示意。
4. **先定连接，再生成路径**：确认视频源、显示端、触控主机、网络及供电关系，再为墙内垂落、检修口、柜背、台面及地板路径分配途经点。设备挪动更新路径，不凭路径猜接线关系。
5. **规划开口**：分别确定屏后孔、对穿孔与检修口；核对进出线位置、柜背对齐及是否仍能检修。孔尺寸待搭建方确认时保留待确认标记。
6. **补齐基础设施**：把 OPS、服务器服务、路由器、交换机、排插/取电点加入关系表。按接口和电源来源分别核对，LAN 与无线关系不能混算实体线缆。
7. **核对用电**：按设备实例、数量、供电方式及功率口径归集到对应取电点；未确认功率、回路与分支容量单独列出。现有估算中的预留数量不是本 POC 已完成的配电设计。
8. **核对并保存当前方案**：核对空间、端口、线路终点、附属跟随、取电及来源。完成导出回导验证后保存本届当前文件，并链接本届项目主档。资料不全时明确标记工作稿，不冒充已冻结最终稿。

每次更换产品，核对型号参数绑定、实际数量、安装尺寸/支架、接口方向与线缆、供电与取电点以及关联开口。若实例用途和位置不变，可沿用实例 ID 更新型号；拆成多台、合并或移除设备时，更新相关引用，不能留下悬空连接。变更原因放在项目文档，页面展示当前有效结果。

## 5. OPS、服务器与网络交接方法：待补齐

既有线材资料将 `Router2 With SIM → Q-NEX Server`、`Router2 With SIM → Lite Media Server` 列为两条 Cat6 连接。主档记录 OPS 型号 `4.PC.ED.I7.Z0013`，适用范围待确认。这些记录不足以断定两个服务共用一台 OPS，也不足以给出操作系统安装命令、服务端口或 IP 配置。

```text
已确认的上网来源 → 路由器 WAN
```
