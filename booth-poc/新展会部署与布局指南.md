# 新展会部署与布局指南（给接手同事）

核对日期：2026-11-13。依据本目录当前源码、锁文件和已有交付记录编写。适用于从迪拜 POC 复用出另一届展会；本次仅整理文档，没有改造或部署新展会程序。

**先记住三件事：沿用现有 Three.js 网页技术即可；先明确设备连接关系，再安排空间走线；当前程序仍是单展会定制版，不能只换一个 JSON 就得到任意新展会。**

产品资料、各类填写表和业务交接见 [交接手册](./交接手册.md)；本指南侧重同事如何接手技术、调整布局、部署和避免重复踩坑。旧手册及 README 保留了多个阶段记录，引用时须核对日期和源码，不能把旧数值累加成当前方案。

## 1. 当前可复用的技术

| 层次 | 当前实现 | 接手建议 |
| --- | --- | --- |
| 页面 | 原生 JavaScript ES Modules、HTML、CSS | 继续使用现有结构即可，不必为了另一届展会先更换前端框架 |
| 三维 | Three.js，`package.json` 声明 `^0.180.0`，WebGL 渲染 | 用盒体、面板、文字占位表现真实外形；确定尺寸和布局后再补外观 |
| 观察及编辑 | `OrbitControls`、`TransformControls`、`Raycaster` | 复用旋转、缩放、平移、选中、轴向拖动和顶部调高操作 |
| 构建 | Vite，声明 `^7.1.7`；实际安装版本由 `package-lock.json` 锁定 | 接手先用锁文件安装，不在首次迁移时同时升级依赖 |
| 参数及检查 | 本地 JS 数据、边界约束和简化包围盒 | 数据以 mm 保存，进入渲染层才除以 1,000 转成 m |
| 保存 | 浏览器 localStorage、JSON 导入导出、会话内撤销重做 | 正式交接保存 JSON 和匹配的源码版本；浏览器缓存只作编辑恢复 |
| 发布 | `dist/` 静态文件，现有实例部署到 GitHub Pages | 可沿用静态托管；网页无需业务后端，现场演示服务器是另一项工作 |
| 检查入口 | Node 内置测试、Vite 构建、人工浏览器交互核对 | 测试和构建通过后，仍需检查实际线路、孔位和存档往返 |

这里的版本是本项目记录，不是“最新版本”推荐。运行环境要求以锁文件中的 Vite `engines` 为准，当前要求 Node.js `^20.19.0 || >=22.12.0`。

性能上已采用按需渲染，静止时不持续绘制，关闭实时阴影和绘图缓冲保留；像素倍率随浏览器缩放更新，上限为 **2.5**。旧文档中的 1.25 已过时。增加高清纹理、阴影或大量标签前，先在同事实际使用的电脑上检查拖动和缩放表现。换成线上托管后，3D 仍在访问者电脑上运行。

## 3. 把程序在另一台电脑跑起来

### 3.1 需要带走哪些文件

准备完整 `booth-poc` 源码目录，包括 `src/`、`index.html`、`package.json`、`package-lock.json`、`vite.config.js`、`tests/`、`scripts/`、两个 BAT 和本地文档。另带用户当前方案 JSON、该届产品参数来源及布局/接线资料。

不要把 `.runtime/` 当作交接数据复制：里面有本机进程记录、日志和旧发布 checkout。`node_modules/` 在目标机重新安装。相邻产品库和展会资料不在 `booth-poc` 内，仅复制程序不会带走它们；需要另外提供实际有权共享的文件或可访问的资料路径。

### 3.2 本地启动

安装符合要求的 Node.js，在复制后的程序根目录打开 PowerShell：

```powershell
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run dev -- --port 5173 --strictPort
```

依赖安装失败时先处理错误，再执行下一条。这里用 `npm.cmd` 可避免 PowerShell 选择到受执行策略限制的 `npm.ps1`。已有锁文件时使用 `ci`；确实需要更改依赖时才更新依赖和锁文件。

打开终端给出的 `http://127.0.0.1:5173/`。也可以在安装依赖后双击 [启动.bat](./启动.bat)，由 [local-server.ps1](./scripts/local-server.ps1) 后台启动并打开浏览器；双击 [关闭.bat](./关闭.bat) 停止该脚本管理的服务。手工 `npm run dev` 启动的服务在原终端按 Ctrl+C 结束，关闭 BAT 不会接管它。

两个 BAT 当前固定使用 5173。要同时开两个展会，可对第二个目录手工运行：

```powershell
npm.cmd run dev -- --port 5174 --strictPort
```

该方式由原终端关闭。不要只改启动参数的一处数字就认为 BAT 已支持新端口：脚本中的 URL、端口占用检查、就绪检查和 Vite 参数必须一致。端口冲突时确认原服务归属，不批量结束所有 Node 进程。

### 3.3 构建与交付网页

在程序根目录依次执行，每一步成功再继续：

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview -- --port 4173 --strictPort
```

构建结果是 `dist/`，预览通常为 `http://127.0.0.1:4173/`。预览用于检查构建产物；正式分享将 `dist/` 的全部内容部署到约定的静态站点目录，保留 `assets/` 和 `THIRD-PARTY-LICENSES.txt`。`vite.config.js` 使用 `base: './'`，便于放在子目录。不要直接双击 HTML，也不要仅复制 `index.html`。

初次安装依赖需要取得 npm 包；构建后的页面资源随包提供，不依赖在线 CDN。展场离线使用前，在目标电脑准备好依赖/产物及本地 HTTP 服务，并实际断网打开验证。`127.0.0.1` 只供本机访问，不能把这个地址发给同事当作共享站点。

现有 [PAGES.md](./PAGES.md) 是**迪拜实例专用**发布记录：[publish_pages.py](./scripts/publish_pages.py) 固定关联 `ToastmastersLee/q`、`booth/` 和原公网地址，里面还有原维护电脑的 Python 路径和 SSH 配置。另一个展会先确定独立发布目录/仓库，再调整发布配置及核验范围；直接照抄原命令可能更新原展会页面。

## 4. 新展会的布局顺序

### 第一步：收齐最少输入

至少确认：正式名称及届次、独立展会 ID、外轮廓或净尺寸口径、长宽高、墙厚、开放方向、各墙设备型号与数量、柜体和讲台用途。未提供的柜体尺寸、安装高度、取电点、网络入口和演示关系先列待确认。

| 要填的内容 | 新展会填写 |
| --- | --- |
| 展会 ID / 名称 / 届次 / 主档路径 | 待填 |
| 外轮廓宽 × 深 / 墙高 / 墙厚 / 地台条件（mm） | 待填 |
| 入口及开放面；墙面编号 | 待填 |
| 各墙设备实例 ID、型号或新品临时名、数量 | 待填 |
| 柜体、讲台、服务器位置及用途 | 待填 |
| 视频源、触控主机及演示组合 | 待填 |
| 场馆取电点、网络来源、已知限制 | 待填 |
| 暂估项、确认人、确认日期 | 待填 |

### 第二步：两路收集产品参数

成熟型号按 [product-comparison SKILL.md](D:/Github/IQ/Q-NEX_PreSale/.agent/skills/product-comparison/SKILL.md) 的 `lookup` 流程，先读分类索引再找准确型号。Q-NEX 中控及讲台通常查 L1，显示设备及 IQ/IQVideo 外设查 L2；PD150 属于 L2，不能只按“讲台”字样归类。换电脑后重新定位这个相邻仓库路径。

尚未入库或参数仍变化的新品，由用户口述、消息、照片、草图或临时规格建立**本届临时参数记录**。尺寸可以先用明确标注的占位值推进讨论；不要求先把新品导入共享产品库。

两路都记录外形宽高深、重量、供电方式、功耗口径、接口类型/数量/方向，以及每个字段的来源、日期和状态。裸机、带支架、包装尺寸分开；典型功耗、最大功耗、适配器额定值分开。缺项写“待确认”，不得以零代替缺失功耗，也不能由屏幕英寸推算整机外形。

每台设备有独立实例 ID，同型号多台分别编号。产品参数更新时，仅主动更新本届参数快照，并重查受影响的尺寸、孔位、连接和供电；不能让共享库变化自动改掉已确认的其他展会。

### 第三步：先做俯视摆位，再做墙面高度

先放墙、柜体、讲台和主要设备外框，检查入口、演示站位、柜门开启、人员通行和维护空间；通道及安装要求依据该展会资料确认，不照搬迪拜尺寸。随后用后墙正视和左右墙立面核对每块屏幕的下沿、上沿、并排间距、柜顶设备遮挡及宣传区位置，最后回到透视视图讨论整体效果。

坐标统一：原点为展位地面中心，X 向右、Y 向上、Z 朝入口；保存的 `bottom` 是物件下沿，不是中心高度。模型中心 Y=`(bottom + height / 2) / 1000`。侧墙设备及侧柜的局部宽度沿世界 Z 方向，深度沿 X 方向；改朝向时必须同时改模型旋转、包围盒和定位规则。

当前 5 m 宽、两侧墙厚各 200 mm，所以左右内墙面为 X=±2,300 mm；后墙内面 Z=-2,300 mm。这是当前展位的推导值，换尺寸后应重算，不作为固定常数复用。50 mm 吸附用于拖动，精确值用毫米输入。

### 第四步：先画连接表，再定孔位和路径

一条线先明确“设备及接口 A → 设备及接口 B、信号方向或电源来源”，再安排屏后入墙、墙内垂落、低位检修口、柜背、台面或地板等途经位置。HDMI 的视频方向和 USB 的触控回传用途分别写清，线画到了柜子附近不等于已经确定接哪台主机。

屏后穿线孔、柜背对穿孔、大检修口分别编号。取电插座是设备，不能画成穿线孔。检修口要核对是否被柜体挡住、柜背孔是否对齐、能否检修，以及施工方确认的尺寸和位置。当前大检修口使用开口周围矩形墙块拼合，调整时重建墙块，无需引入复杂布尔建模；当前 `hole` 小孔仅为圆环标记，不会真的切开墙体。

柜子移动时，其柜顶设备和柜内排插随动，墙上检修口保持独立；两者之间的路线重新生成。后墙多屏到讲台的线应分别保留 ID、来源名称和偏移通道，在俯视图能数清每一条。地板下 Y=-30 mm 仅是当前显示层次，不能当作施工开槽深度。路径长度不能直接作为采购线长，真实接口、弯折和余量另行核对。

### 第五步：补齐供电、网络和服务器

按设备实例补齐“场馆取电点 → 排插/PDU → 设备”和“上网来源 → 路由器 → 交换机 → 终端/服务器”关系。PoE 设备记录供电端口及能力，不因有 LAN 线就推定已经供电。未知功耗与未知回路单列；不能用已知设备的小计代表完整总负载。

OPS 是硬件，Q-NEX Server、Lite Media Server 是需确认的服务；分别记录承载关系，不默认共用一台机器。填写 OPS 独立运行底座与供电、安装位置、系统、服务版本、IP/端口、上网要求、安装包和启动步骤。网页静态托管成功，不能替代这套现场系统的部署验收。详细填写表见 [交接手册](./交接手册.md)。

## 5. 改另一个展会，要改哪些代码

短期可保留一份独立工作副本完成新展会，但明确源码版本、展会 ID 和交付地址，保护原展会文件。长期采用“一个共用程序 + 每届独立数据”，避免多份代码长期分叉。目前页面没有多展会切换器。

| 文件 / 位置 | 需要同步处理的内容 |
| --- | --- |
| [layout.js](./src/layout.js)：`BOOTH`、`INITIAL` | 展位数据、设备清单/稳定 ID、型号文字、尺寸、位置和来源；更名不应误改仍被引用的 ID |
| 同文件：`worldSize`、`constrain`、`bounds`、`checkLayout` | 新朝向、内墙边界、最大尺寸、落地/贴墙规则；当前有 2300、2500、4000 等固定数值 |
| 同文件：`syncAttachments` | 柜顶、柜内、屏后孔及插座跟随；目前有特定设备 ID、固定高度及左右柜规则 |
| 同文件：`parseLayout` | 当前为固定 ID 白名单和旧版本迁移；新增任意设备/墙体不是改 JSON 就能导入，需要同步格式与校验 |
| [wiring.js](./src/wiring.js)：`CONNECTIONS` | 增删设备时同步增删起终点和检修口引用；不能留下不存在的 ID |
| 同文件：`cableRoutes` | 固定墙内坐标、地板段、设备专用路径、信号分线；按新展位重算，不复制旧折点 |
| [main.js](./src/main.js)：场景构造、`updateWalls` | 地板、墙、开口、门头、装饰条和标尺都含固定几何尺寸；只改 `BOOTH` 不会同步更新这些部分 |
| 同文件：模型、相机与编辑 | 新物件 `kind` 的造型和朝向；相机取景、缩放范围、面板输入限制、拖动约束、线路说明标签 |
| 同文件：保存/导出/旧稿入口 | 换独立保存键、导出项目标识及文件名；制定本届迁移策略，不能继续把“载入旧稿”指向迪拜键 |
| [index.html](./index.html)、[style.css](./src/style.css) | 展会名称、标题、尺寸卡片、假设说明、默认恢复按钮及窄窗口可操作性 |
| [tests/layout.test.js](./tests/layout.test.js) | 将本届期望尺寸、连接和迁移要求写入检查；不要把原展会测试成功当作新展会验证 |
| [local-server.ps1](./scripts/local-server.ps1)、发布脚本 | 多实例端口与本机启动方式、目标站点/目录及发布核验范围 |

通用化时，优先抽出 `projectId`、展位尺寸/墙面、设备实例、父子关系、参数快照、开口和连接表，让几何、约束、路径与相机读取同一份数据。新格式的导入器要真正使用这些字段，并检查引用完整性；不要只有导出字段看上去通用。

每届最终稿可约定放在该届 `模拟方案/current.json`，并在主档链接对应程序版本；这是建议目录结构，不是当前程序自动生成的功能。过程讨论和替换原因继续放项目 Markdown/Excel。后续展会规划 skill 可整理流程和核对步骤，具体产品与展会参数仍放数据文件。

## 6. 已踩过的坑，以及当前仍需留意的限制

| 问题 | 经验 / 接手处理 |
| --- | --- |
| 文档里同时存在多个版本的尺寸和数量 | 旧 19/21 件、12/15 条线、右柜 PoE 节点说明不代表当前代码；核对最新版源码、用户确认及图纸，并保留冲突来源 |
| HDMI 和 USB 完全重叠，误以为一根线消失 | 每根线保留身份并错开显示；同时开启、单独开启和选中设备时都检查；不能只验证连接数组里有该条记录 |
| CPL50 终点曾放错；UK Socket 曾被当作穿线孔 | 改动前后逐条比较起止设备；插座、孔、排插分别建模，未知端口标待确认 |
| 导出曾标 v1 却包含新版物件，导致回导失败 | 当前已使用 v4，不能继续把旧问题描述成当前故障；以后改格式时同步保存、导出、导入、迁移和实际按钮验证 |
| 修改默认布局后，页面仍显示旧位置 | localStorage 会恢复用户编辑；先导出保护已有方案，再在独立测试环境检查默认值，不随意清空用户缓存 |
| 两个展会部署到同一域名的不同目录 | localStorage 按来源而非 URL 路径隔离；同域不同目录若沿用同一保存键会互相覆盖，必须加入展会 ID |
| 端口/域名变化后“方案不见了” | `127.0.0.1:5173`、5174、4173、localhost 和线上属于不同来源；用 JSON 搬运，不能依赖缓存自动同步 |
| 提高画质后拖动卡顿，降低倍率后文字模糊 | 保持按需渲染和适度像素倍率，检查浏览器缩放及不同屏幕；当前上限 2.5，不保证所有电脑帧率 |
| 动态重建导致不必要开销或更新不出现 | 复用 `dispose` 清理几何/材质/纹理；拖动非开口物件无需重建墙；新交互修改场景后触发 `invalidate()` |
| 把包围盒“通过”当作完整布局验收 | 当前检查排除了多种附属物及前框物件；仍需人工核对柜顶放得下、检修可达、遮挡及通行 |
| 复制发布脚本更新了原页面 | 发布路径和远端是固定的；先确认新展会目标，只发布构建目录并核对实际页面 |
| 只测构建，没有看浏览器 | 本地测试不能证明线看得见、开关正确或文件回导成功；保存真实交互结果及未完成项 |

另有以下**本次源码审阅发现的局限，尚未在本次修改程序**：

- `cableRoutes` 的后墙分支同时用于电源和信号，后墙电源目前也经过 Y=-30 的示意折点；不能据此宣称电源只在检修口附近直落。
- HDMI/USB 的 ±45 mm 分线偏移也应用于终点坐标；线条并不精确落在目标物件中心或真实接口。新展会应让各线拥有明确接口占位点，只对中间路径错开，并检查末端。
- 当前每条路线统一标记为隐藏的“示意暗线”，不是按每一段分别识别墙内、柜内和地板下；部分说明标签也是固定文字，换设备要同步更新。
- 导入器对 `poe-node` 使用默认值，旧版 `right-laptop` 迁移也有特殊处理；新增网络节点及保存移动位置时要专门核对往返结果。
- 当前台面附属约束不构成“大设备一定放得下”的证明；柜深变小或新品变大时，单独比较设备世界坐标外框与台面范围。
